## Diagnóstico

O pipeline `pipeline.py` e `packages/cli/kernel/core.py` requerem 3 variáveis de ambiente:

| Variável | Uso | Sensibilidade |
|---|---|---|
| `SUPABASE_URL` | Endpoint da API | Público (ok) |
| `SUPABASE_SERVICE_KEY` | Admin — write/delete | ALTA — não commit |
| `SUPABASE_ANON_KEY` | Read-only | MÉDIA — pode commit em .env.example |

**WO F02-04 status:** `HOLD_NO_CREDENTIALS` — schema inspection blocked
**WO F06-04 status:** `HOLD_NO_CREDENTIALS` — 128 WOs, cannot determine what's in Supabase

---

## Passo a Passo

### Passo 1: Obter credenciais do Supabase

1. Acesse https://supabase.com/dashboard
2. Selecione o projeto `calculadorasdeenfermagem` (ou criar novo)
3. Vá em **Settings → API**
4. Copie:
   - `Project URL` → `SUPABASE_URL`
   - `service_role` ou `anon` → `SUPABASE_SERVICE_KEY` (para write) ou `SUPABASE_ANON_KEY` (para read-only)

### Passo 2: Adicionar como Secret no GitHub

1. Repo: `IndiciumFIN/calculadorasdeenfermagem`
2. Settings → Secrets and variables → Actions
3. New repository secret:
   - Name: `SUPABASE_URL`
   - Secret: `<valor copiado>`
4. Repetir para `SUPABASE_SERVICE_KEY` (ou `SUPABASE_ANON_KEY` para read-only)
5. Adicionar ao workflow que usa (ex: `drive-recursive-collect.yml` ou novo workflow)

### Passo 3: Atualizar workflow se necessário

Se o workflow `drive-recursive-collect.yml` ou outro precisa de Supabase, adicione:

```yaml
- name: Run Supabase WO reconciliation
  env:
    SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
    SUPABASE_SERVICE_KEY: ${{ secrets.SUPABASE_SERVICE_KEY }}
  run: python -c "from packages.cli.kernel.core import sync_wo_state; sync_wo_state()"
```

### Passo 4: Verificar

Após adicionar secrets, o WO F02-04 pode executar a inspeção do schema.
Confirme via: `gh run list --workflow=gate.yml` ou manualmente:

```bash
curl -H "apikey: $SUPABASE_SERVICE_KEY" \
  "$SUPABASE_URL/rest/v1/?limit=1" | jq .
```
